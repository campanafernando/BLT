# BLT knowledge vault

Durable knowledge for agents and people: what cannot be derived from symbols. CodeGraph covers
code; this vault covers rules, contracts, provenance and decisions. Markdown is the source of
truth, and if a note and the code disagree, the code wins and the note gets fixed.

This file is user-owned: FEFO creates it once and never rewrites it. Because FEFO regenerates
`00-INDEX.md`, **this file is the index of the BLT notes** (the generated index only lists
federation, decisions and repository notes).

| Note | Read it when |
|---|---|
| [`layout.md`](layout.md) | choosing where a change belongs; what is frozen; the check commands |
| [`domain.md`](domain.md) | touching tasks, visibility, assignment, status, notifications |
| [`contracts.md`](contracts.md) | changing an endpoint, the error shape, auth or `types.ts` |
| [`spec-flow.md`](spec-flow.md) | touching the Gitea → spec → issue/tasks flow or the prompt |
| [`mcp-and-secrets.md`](mcp-and-secrets.md) | touching an MCP server, a role, a credential |
| [`decisions.md`](decisions.md) | asking "why is it like this" before changing it |
| [`repos/api.md`](repos/api.md), [`repos/web.md`](repos/web.md) | onboarding to a federated repository |

Generated by `./bin/fefo sync` (do not edit by hand): `00-INDEX.md`, `federation.md`, and the block
between the `fefo:generated` markers in `repos/*.md`.

## Rules for notes

- Header says what was verified: date and revision of each repository.
- Every rule points to a file and, when one exists, the test that proves it.
- No secret, password, token or personal data; no task list (the plan is in `docs/plan.md`).
- A decision goes in `decisions.md` with date, context, decision and consequence.

Other BLT documents stay where they are: `docs/HANDOFF.md` (state), `docs/plan.md`,
`docs/architecture.md` (reasoning), `docs/mcp.md`, `docs/ai-log.md`, `docs/tasks/mvp.md`.
