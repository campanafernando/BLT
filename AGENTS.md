# BLT — agent rules

## Context

`BLT` orchestrates; `blt-project` implements. `blt-project/api` is Django 6 + DRF,
`blt-project/web` is React + Vite + TypeScript, and `blt-project/api/hypermedia` is the
server-rendered client with HTMX + Alpine.js.

## Code boundaries

- `tasks/views.py` only validates input, calls a service and returns a response.
- Business rules live in `tasks/services.py`. Never in a view, serializer or template.
- Queries and filters live in `tasks/selectors.py` and `tasks/filters.py`.
- `hypermedia/views.py` calls the same `services` and `selectors` as the API. Duplicating a rule is forbidden.
- `web/src/lib/api.ts` is the only place that speaks HTTP. Components do not build URLs.
- `web/src/features/<area>/` groups the hook, component and types for that area.

## Contract

- The OpenAPI schema is generated by `drf-spectacular`; the React client is written by
  hand against `web/src/lib/types.ts`. If the contract changes, update both.
- Errors follow the DRF format (`detail`, or field → list). The frontend reads both.

## Tests

- `pytest` with `pytest-django`. Every new rule has a service test and an endpoint test.
- Minimum coverage: 80% (`make test` fails below it).
- Do not use `time.sleep`, the real clock or the network in tests. Freeze dates with
  `freezegun` when behavior depends on "today".

## Style

- Python: ruff, line-length 100, double quotes, sorted imports.
- TypeScript: no implicit `any`; small functions; server state in TanStack Query.
- CSS: design tokens in one `index.css`; the React client uses Tailwind utilities over them, the HTMX client plain CSS; no component library.
- Comments only for the "why" the code cannot show.

## MCP

- One server per source. Plain configuration is in `.env`; passwords and keys are files in
  `secrets/`. Neither goes in `opencode.json`, `.mcp.json` or the FEFO manifest.
- `postgres-blt` and `minio-blt` are read-only by construction. Do not add a write tool
  without reviewing the contract and the database role.
- `blt-specs` writes only issues (with Gitea credentials configured) and, with `confirm=true`, tasks.
- The scaling pattern is the FRETE-E gateway; here the launchers play the routing role.

## Forbidden

- Committing without authorization.
- Putting a secret, token or key in versioned code.
- Adding a dependency for a three-line task.
- Leaving a warning in the browser console or a warning from `manage.py check`.
